# 开源整理与独立验收

验收日期：2026-10-30。范围为本仓库公开文件，不包含原开发者的数据库或自动化状态。

## 结果

- 以白名单从核心源码和单元测试构建，未整体复制生产项目。
- 原项目在系统临时目录保存文件清单、大小、mtime、inode、模式及文件 SHA-256，交付时再次比对；Git 命令执行数为零。
- 目标仓库原先只有 .git，交付保持该目录不变。最终核对：原项目 1000 个文件/目录条目清单一致，所有普通文件内容与元数据一致；仅 tmp 目录 mtime 改变。目标 .git 的 26 个条目内容与元数据全部一致。
- 公开工作树仅含文本源码、合成夹具、配置、中文文档、Skill、CI 和许可文件，不含真实语料或二进制文件。
- 自有代码采用 MIT，未能核实具体个人版权归属，因此使用 2026 PaperRadar contributors。

## 原项目只读边界偏差

本次不能宣称原项目的全部文件系统状态完全不变：只有 tmp 目录修改时间发生变化，没有文件增加、删除或内容变化。创建独立临时虚拟环境时曾继承原环境脚本设置的 TMPDIR，可能触发 Python 安装组件在该目录短暂创建并清理临时项；应按本次操作可能造成的目录元数据变化记录，不能归因于外部运行。未尝试恢复时间戳或清理原目录。原代码、数据库、配置、日志及 Git 数据没有文件变化，但“原项目完全不变”的严格元数据验收不满足。

## 审计结论与修改

核心链路为 radar.py → tracking → core 的 arXiv/OpenAlex 接口与解析器 → SQLite → weekly。Python 核心只需要标准库和 curl。原 env.sh、skills.lock.json 及项目 Skill 存在本机路径；公开版改用仓库相对路径和随库解析器。第三方三个文件及许可证与原项目保存的固定上游副本逐字节相同，运行时仍校验哈希。

已有通用主题机制将未知主题标为待筛选，保留该机制；蓝光规则只在配置显式启用时使用。窗口检索支持主题自己的检索组并校验组 ID，保留旧策略名称和默认单页行为。不重构去重、SQLite 事务、增量身份冲突及人工判断保护。

去掉只适用于个人第一阶段迁移的 bootstrap CLI；第一阶段历史报告组装、逐条个人判断、原生任务登记/准备、账号设置和本机 Codex 运行时探测脚本不发布。原生验收失败收尾场景的辅助脚本仅在 tests/helpers 保留，使用模拟状态测试，不附带授权或任务文件。

测试不再读取真实检索快照：原有 67 个测试方法和断言场景保留，改用合成 TEST DATA 输入；另增 5 项通用主题、目录约束、哈希拒绝与离线闭环测试。原生产代码与测试未修改。

## 实际执行

在独立临时副本创建全新 .venv，设置空 HOME，清空继承环境变量，仅提供系统 PATH；不加载原开发者 Skill、Key 或配置。

```bash
python3 -m venv .venv
source scripts/env.sh
python -B scripts/check_install.py
python -B scripts/radar.py --help
python -B -m unittest discover -s tests -v
python -B tests/offline_demo.py
```

结果：独立副本和最终目标目录均为 72 项通过，0 失败、0 跳过；实际 Python 3.12.14。目标目录使用独立虚拟环境运行，未在公开工作树留下虚拟环境。安装校验确认语法、示例配置、解析器哈希、curl 与 Skill 文件存在。离线演示模拟 HTTP，真实执行解析、首次入库 1 条、重复新增 0 条、通用主题待筛选、两条运行历史、SQLite integrity_check=ok 以及 Markdown/引用校验输出。临时合成数据库自动清理。

使用公开网络匿名发起 arXiv 和 OpenAlex 各一次最多 1 条检索，两者均成功返回并解析 1 条；没有访问凭证或调用付费模型。原始响应保存在系统临时验收副本，未发布。在线探测未执行真实语料入库和研究语义复核，不能声称完成全主题在线端到端评价。
